# 事故记录：3.0.0 重装导致 DSH 崩溃（2026-11-22）

## 症状

从 tarball 卸载重装 `dsh-wtskin-project` 时 DSH 下线（GUI 断开），重启后恢复。

## 根因

1. **主因：插件把宿主核心包钉成了普通依赖。**
   `package.json` 的 `dependencies` 固定写死 6 个 `@deepseek-ai/*`（`0.2.1-rc.3`）：
   `dsh-tools`、`dsh-tool-fs`、`dsh-tool-todo`、`dsh-tool-web`、`dsh-tool-ask-user`、`dsh-time-context`。
   pnpm 把它们实体化进 `profile/node_modules`；宿主升级到更新版本后，profile 里的旧副本在解析顺序上**顶替**了宿主自己的新版本，
   "插件依赖宿主"变成"插件替换宿主"，宿主启动失败。
   对照：官方 `dsh-builtin-browser` 对同类包用的是 `peerDependencies: ">=0.1.1-rc.2 <0.3.0"`。

2. **次因：pnpm 覆盖安装时的 EPERM。**
   旧的 `link:` 安装是一个目录符号链接，pnpm 无法把临时目录 rename 到它上面：
   `[ERR_PNPM_EPERM] rename ...node_modules/dsh-wtskin-project_tmp_55880_13 -> ...dsh-wtskin-project`。
   这不是崩溃根因，但让安装失败并留下半成品目录。

## 证据

- `package.json`（3.0.0）：`dependencies` 中 6 个精确版本；
- profile 的 `node_modules`：安装后出现 `@deepseek-ai/*` 的旧副本（重装 3.0.1 时被 pnpm 清掉，`Packages: +3 -24`）；
- `.plugin-manager/logs/operation-WMCavc/pnpm.log`：上面的 EPERM；
- 冒烟测试在**没有**这些依赖时全过，说明插件运行时并不需要它们。

## 修复（3.0.1）

- **3.0.1**：6 个包从 `dependencies` 移到 `peerDependencies`（`">=0.1.1-rc.2 <0.3.0"`，`optional: true`）；
- **3.0.2（最终）**：干脆去掉全部 `peerDependencies`——插件**不声明任何宿主包、不与 DSH 版本关联**，运行时按可用性解析；
- 运行时缺失时走插件内置回退（`parametersToJsonSchema`、app.asar 路径解析、`defineTool` 兜底）；
- 版本 3.0.1，重新打包并安装验证。

## 附带损失与恢复

- 崩溃同时破坏了仓库的 `.git` 元数据（HEAD/config/index 丢失，仅剩 `objects/`、`refs/`）。
- 用残留对象恢复：`refs/heads/main` 指向 `92ca11a`，重建 `.git` 后 `git reset --hard 92ca11a` 恢复了完整历史；
- 3.0.1 的改动重放为提交 `3e82037`；remote 重新指向 GitHub。
- 旧 `.git` 备份与临时文件已清理。

## 打包与安装校验（3.0.1）

```
dist/dsh-wtskin-project-3.0.1.tgz
sha256: ebcf4e17f7abc1bb126ef6c3ed3d8bbea21d3f89d3f78ff181e01bfc3c4fb3b4
18 个文件，逐文件哈希见 dist/manifest.json 与 dist/SHA256SUMS.txt
```

卸载 link 安装 → 从 tarball 安装 → 比对：**18/18 哈希一致**；
安装目录多出的 `.preset-status.json` 是插件运行时诊断文件，不属于包内容。

## 教训

1. **永远不要**把宿主核心包写成 `dependencies`；用带范围的 `peerDependencies`（可选）。
2. 覆盖安装前先确认旧安装不是符号链接（`link:` 安装会留下 symlink）。
3. 打包产物要记录哈希，并从产物回归安装一次。
4. `.git` 也值得备份——崩溃可能伤到仓库元数据。
