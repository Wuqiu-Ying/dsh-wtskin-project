# 精确确定「目标面」坐标的方法调研

> 2026-11-15。目标：不靠人眼估，把插图精确落到涂装映射图的某个面（UV 岛）上。
> 结论写在最前：**没有现成的开箱方案**；最可行的是「参考涂装差分」+「面板内交互式区域生长」两条路。

## 一、旧工作台（session-0297e24a，Q-5L 时期）实际用的方法

那次没有自动识别，靠四件事组合：

1. **直接看 4096 贴图的 UV 布局**：人工从贴图上认出"右下两片带五角星的大三角＝机翼上下表面"、"上方长条＝机身侧面"、"左侧＝垂尾/平尾"。坐标是估的。
2. **反推现成痛机的落点**：下载 WT Live 上同机型的二次元涂装，看角色落在贴图的哪块，再照抄位置（"位置参照了艾丽妮痛机的实际落点"）。
3. **用户量坐标**：用户在 1600 的 `preview.png` 上用四点框选，报给模型；模型按 `4096/1600` 换算。
4. **截图迭代**：装进游戏截图，按偏差平移/缩放（例如"向上移动 100px（1600 坐标系）"），直到看着对。

这套办法的问题就是慢：每一版都要"装游戏 → 截图 → 回来改"。

## 二、实测的四种候选方案

### A. 参考涂装差分（推荐，精度高、可自动化）

思路：同一机型的真实痛机 `_c.dds` 减去原版贴图，得到"被作者画过的 UV 区域"；
连通区域 + 最小外接矩形 = 真实被使用的面板。旧会话的"反推落点"就是它的人工版。

- 优点：直接得到"人类实际用的面"，数量/形状都可信；不依赖贴图颜色是否均匀。
- 成本：要从 WT Live 下载同机型涂装（接口可拿），再解 DDS。
- 适合做成一次性模板工具：对每个机型产出 `faces-template.json`。

### B. 面板内交互式「区域生长 / 魔棒」（推荐，实时、可交互）

点击面板内一点，按亮度容差生长，得到该面区域，再拟合多边形/最小外接矩形。

实测（F-104G 模板，1024 采样，容差 ±14）：

| 种子（画布坐标） | 结果 |
| --- | --- |
| (3300,900) 右上翼 | 区域 13905px，包围盒 (3104,648)-(3728,1376)，**与翼板吻合** |
| (3300,2900) 右下翼 | 6999px，(3232,2804)-(3760,3468)，**吻合** |
| (2000,1000) | 575px —— 种子落在徽标里，被徽标边界困住 |
| (2000,2900) | 12920px，但向左漏到相邻亮区 (1008,2740) |

- 结论：右侧稳，左侧会漏。需要加**梯度屏障**（强边缘不跨越）和**面积上限**，并自动把种子从徽标中心挪开。
- 优点：面板内可做，用户点一下就有候选四边形；缺点：贴图明暗均匀时容易漏。

### C. CDK / Blender 导出 UV 岛（最精确，最重）

用战争雷霆 CDK 打开模型，或社区 Blender 插件导出 UV 布局，直接拿到每个 UV 岛的轮廓。

- 优点：几何真值，绝对精确。
- 缺点：要装 CDK/Blender、处理游戏资产，无法在面板里即时用；适合"每个机型做一次模板"。

### D. 法线贴图分割（实测不可用）

想按"平面法线一致"把翼面分出来。实测 F-104 模板的法线图整片归一
（前 3 个主方向就覆盖了 30 万+ 像素），翼面之间没有可区分的法线差异 → **这条路对本套模板无效**。

## 三、建议的落地顺序

1. **B（魔棒）先进面板**：点一下 → 区域生长（亮度容差 + 梯度屏障 + 面积上限）→ 填充徽标孔洞 → 最小外接矩形 → 直接变成当前面的四边形。用户可再手动拖点微调。
2. **A（参考涂装差分）做成模板工具**：对常用机型离线跑一次，产出预置面；新工程直接套。
3. C 只在需要极致精度时用，不进日常流程。

## 四、面板交互上的配套

- 魔棒结果给出后，仍保留手动四点/多点编辑（现状）；
- 「旋转 180°」「弦长占比」已经在面板里（上翼面倒置、85% 弦长是旧会话的实测经验）。
